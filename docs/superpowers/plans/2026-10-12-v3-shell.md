# Plan V3-2: Shell (providers, session, controller, canvas)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `LatticeCanvas` that mounts an empty canvas with working viewport plumbing, a user-owned `LatticeController`, and public Riverpod selectors readable in the subtree.

**Architecture:** Controller owns its `ProviderContainer` (no override-remount hazards; options/theme/registries are plain controller fields exposed via `LatticeScope`). Document commits notify controller listeners (`ChangeNotifier`); session ticks never do.

**Tech Stack:** Flutter, flutter_riverpod 3.x (`NotifierProvider`, `select`), widget tests.

**Spec:** `docs/superpowers/specs/2026-10-12-lattice-rewrite-design.md` (§3.1, §4)

## Global Constraints
- SDK `^3.10.0`, Flutter `>=3.35.0`; deps flutter + flutter_riverpod only; no codegen.
- TDD + commit per task. New code in `lib/src/v3/`; tests import `package:lattice/src/v3/...`. No `lib/lattice.dart` change.

## Review Focus
- Controller used before canvas mount → method calls throw `StateError` with actionable message (not null crash). Pinned in Task 2.
- Two canvases sharing one controller → second mount throws (one container, one canvas). Pinned in Task 3.
- Options object replaced each build (fresh instance, same values) → no rebuild storm; widgets read fields, not provider. Pinned in Task 3.
- Selection emission reuses identical set instances when unchanged → `select` subscribers skip. Pinned in Task 1.
- Controller dispose with canvas mounted → container disposed once, no double-dispose crash. Pinned in Task 2.
